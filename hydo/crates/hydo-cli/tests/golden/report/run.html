Redis lost data it had confirmed, after a power cut, with Redis appendfsync set to everysec

Your workload ran 12 steps and Redis confirmed all 12. Then the power was cut before the 13th step. When Redis started again, key k:0 was gone.

Your check failedredis.acked_writes_survive: every SET the client saw acknowledged reads back with its value

When it happens

  1. The disk keeps recent writes in a cache that a power cut loses, as real disks do.
  2. Redis appendfsync is set to everysec, not its safe value always.
  3. The power goes out after 12 steps, before the 13th step.
  4. After the restart, your check finds key k:0 lost.

Is this a bug?

Expected for this setting

Redis appendfsync is set to everysec, and its safe value is always. With that setting, a power cut can lose data that the system had already confirmed.

A second run with Redis appendfsync at always instead of everysec passed every check.

What to do: If confirmed data must survive a power loss, keep Redis appendfsync at always. If losing it is fine for you, accept this finding.
