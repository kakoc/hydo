# The test tiers of the workspace (Milestone 171; docs/CI.md "Test tiers"). One line per test
# binary, as cargo-nextest names it, and its tier:
#
#   fast  run on every push and pull request (ci.yml, for the packages the change can affect:
#         ci/affected-packages.sh) and in the full tier;
#   full  run in the full tier (ci-full.yml every night, on demand and before a release:
#         `cargo test --locked --release --workspace`, docs/RELEASING.md step 1), and on a push
#         that changes a file of the binary's own package (ci/tier-filter.sh).
#
# `full` is for the large equivalence corpora against recorded answers (thousands of cases, ten
# seconds or more each) and for documentation examples (cargo-nextest does not run those).
# hydo-release's test_tiers fails when a test binary of the workspace has no line here or a line
# names none; add a new binary as `fast` unless it is such a corpus.
